# OctoAcme Project Management

This page is the starting point for OctoAcme's project management guidance. Projects move through **initiation, planning, execution, release, and retrospective/continuous improvement**. Initiation validates the need, intended outcomes, stakeholders, and initial risks. Planning turns an approved initiative into prioritized work with acceptance criteria, a Definition of Done, dependencies, and milestones. During execution, teams deliver incrementally on a project board and monitor risks. Release preparation includes pre-release checks and a rollback plan, followed by staged deployment and smoke verification, post-deployment checks, and stakeholder updates. Retrospectives turn lessons from sprints, releases, and incidents into owned action items.

The **Project Manager (PM)** coordinates delivery, schedules, risks, and communication; the **Product Manager (PdM)** owns product outcomes and prioritization. **Developers** build and test the solution, **QA** validates quality and acceptance criteria, and **stakeholders** provide input and approvals.

Teams share regular progress and stakeholder updates, keep blockers and risks visible, and escalate issues through the PM and appropriate leads. Quality practices include small pull requests linked to issues and acceptance criteria, required review, automated tests, linting and security scans, integration tests where appropriate, smoke tests for critical flows, and manual QA when needed.
